## 一、机器人为什么要话题通信

一个机器人身上装了很多**传感器**（感知环境）和**执行器**（执行动作）：

| 类别 | 例子 |
|------|------|
| 传感器 | 摄像头、激光雷达、激光测距单元、IMU |
| 执行器 | 底盘、机械臂关节、电机、电动夹爪 |

它们之间要互相传递数据，ROS2 为此引入**订阅-发布机制**（话题通信）。

**类比（公众号订阅）**：
- 作者写文章发布 → **发布者**
- 读者关注公众号 → **订阅者**
- 公众号名字（凭名字才能找到内容）→ **话题名**
- 内容是文字/图片/视频（类型）→ **消息类型**

> 补充：物联网里的 **MQTT 协议**也是订阅-发布机制——这套思想在工业界很通用。

---

## 二、话题通信的四个关键点（框架）

> **发布者、订阅者、话题名、话题类型**——记住这四个，话题通信就通了。

| 关键点 | 通俗含义 | 类比公众号 |
|--------|---------|-----------|
| **发布者** | 创建数据、往外发的一方 | 作者 |
| **订阅者** | 接收数据的一方 | 读者 |
| **话题名** | 数据的"频道名"，双方靠它对接 | 公众号名 |
| **话题类型** | 数据长什么样（消息接口） | 内容形式（文字/图片/视频） |

**硬性规则**：发布者和订阅者必须 **话题名一致 + 消息类型一致**，否则频道对不上。

## 三、turtlesim 实操：小海龟模拟器

turtlesim 是 ROS2 自带的小游戏：一只小海龟，**发布者控制它，订阅者看它位置**——四个关键点全在里面。

### 第 1 步：启动小海龟

```bash
ros2 run turtlesim turtlesim_node
```

弹出一个蓝色窗口，一只小海龟在中间。

### 第 2 步：查看节点列表和信息

```bash
# 新终端
ros2 node list          # 看到 /turtlesim 节点
ros2 node info /turtlesim   # 查看它的订阅者和发布者
```

`node info` 输出里会看到：

```
Subscribers:
  /turtle1/cmd_vel     类型: geometry_msgs/msg/Twist   ← 谁发控制指令给它
Publishers:
  /turtle1/pose        类型: turtlesim/msg/Pose        ← 它实时报自己的位置
  /rosout              ...
```

**两个话题的含义**：
- `/turtle1/cmd_vel`：控制话题（让小海龟怎么动）
- `/turtle1/pose`：位置话题（小海龟实时在哪）

### 第 3 步：订阅位置话题，看数据

```bash
ros2 topic echo /turtle1/pose
```

输出：

```
x: 5.54
y: 5.54
theta: 0.0
linear_velocity: 0.0
angular_velocity: 0.0
```

**五个数据的含义**：

| 字段 | 含义 |
|------|------|
| x / y | 小海龟的坐标位置 |
| theta | 脑袋朝向（**弧度**，最大 ±π，不是角度） |
| linear_velocity | 线速度（往前走多快） |
| angular_velocity | 角速度（原地转多快） |

## 四、线速度 vs 角速度（开车类比）

| 概念 | 通俗理解 | 正负号 |
|------|---------|--------|
| **线速度** | 车头方向往前/往后开的速度 | 前进 > 0，后退 < 0 |
| **角速度** | 原地转圈的速度 | 逆时针（从上往下看）> 0，顺时针 < 0 |

**记忆**：线速度 = 开车的快慢；角速度 = 转方向盘的快慢。

## 五、消息接口：Twist 长什么样

想发布控制话题，先搞清楚消息类型。两种查看方式：

```bash
# 方式1：从节点信息里看到类型名
ros2 node info /turtlesim

# 方式2：查话题信息
ros2 topic info /turtle1/cmd_vel

# 方式3：看消息接口的详细定义
ros2 interface show geometry_msgs/msg/Twist
```

`Twist` 的完整结构：

```
geometry_msgs/msg/Twist
├── linear（线速度）        ← 一个 Vector3 结构
│   ├── linear.x   （前后）
│   ├── linear.y   （左右，平面车用不到）
│   └── linear.z   （上下，平面车用不到）
└── angular（角速度）
    ├── angular.x  （绕x轴翻，平面车用不到）
    ├── angular.y  （绕y轴翻，平面车用不到）
    └── angular.z  （绕z轴转，平面车用这个）
```

**为什么平面小海龟只用 `linear.x` 和 `angular.z`？—— ROS 坐标系**：

```
ROS 右手坐标系：
  x 轴 → 朝前（车头方向）
  y 轴 → 朝左
  z 轴 → 朝上（屏幕朝向你的方向）

小海龟在平面上：
  只能前后走 → 只用 linear.x
  只能平面转 → 只能绕 z 轴转 → 只用 angular.z
  绕 x/y 轴转 = 翻车，不存在的
```

## 六、用命令行发布话题（控制小海龟）

### 基本命令

```bash
ros2 topic pub /turtle1/cmd_vel geometry_msgs/msg/Twist \
"{linear: {x: 1.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
```

小海龟以 1 m/s 往前跑。

### 四个参数对照

| 参数 | 内容 |
|------|------|
| 话题名 | `/turtle1/cmd_vel` |
| 消息类型 | `geometry_msgs/msg/Twist` |
| 数据内容 | `"{linear: {...}, angular: {...}}"`（YAML 格式） |

### YAML 格式规则（必记）

1. **大括号 `{}`** 表示一层结构：`linear` 下面还有 `x/y/z`，就要再套一层 `{}`
2. **冒号 `:` 后面必须有一个空格**：`x: 1.0` 不能写成 `x:1.0`
3. 层级关系：`{linear: {x: 1.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}`

### 各种动作

| 想干什么 | 数据怎么写 |
|---------|-----------|
| 前进 | `linear.x = 1.0` |
| 后退 | `linear.x = -1.0` |
| 原地逆时针转 | `angular.z = 1.0`（正 = 逆时针） |
| 原地顺时针转 | `angular.z = -1.0`（负 = 顺时针） |
| 画圆 | 同时给 `linear.x` 和 `angular.z` |

### 发布频率：-r 参数

```bash
ros2 topic pub -r 10 /turtle1/cmd_vel ...   # 每秒发布 10 次（默认 1 次）
```

**重要区分**：发布频率（-r）只影响"发得多频繁"，**小车速度由 `linear.x` 和 `angular.z` 的值决定**——频率调到 10 车不会更快，只是控制指令更连续。

## 七、命令行工具全家（本节实操汇总）

| 命令 | 干什么 |
|------|--------|
| `ros2 node list` | 查看运行中的节点 |
| `ros2 node info <节点名>` | 查看节点的订阅者、发布者、话题和类型 |
| `ros2 topic list` | 查看所有话题 |
| `ros2 topic echo <话题名>` | 实时输出话题数据 |
| `ros2 topic info <话题名>` | 查看话题类型、发布者/订阅者数量 |
| `ros2 interface show <消息接口>` | 查看消息接口的详细定义 |
| `ros2 topic pub <话题名> <类型> <数据>` | 发布话题数据 |
| `ros2 topic pub -r <频率> ...` | 按指定频率发布（默认 1Hz） |

**思路**：先 `node info` 或 `topic info` 查出"话题是什么类型"，再 `interface show` 看结构，最后 `topic pub` 发布——三步走，控制任意机器人节点。
